$$QF$$ batch syntax

      
    

    

      

        
Substitution

        
Attach a .txt query file — one value per line — with the Query file… button. Put $$QF$$ anywhere in the URL, a header value, or the body, then Send fires one request per line, replacing every $$QF$$ with that line's value.

        
https://api.example.com/search?q=$$QF$$

      


      

        
Stop condition

        
$$QF::<...>$$ stops the whole run the moment a response matches the condition inside the brackets.

        
$$QF::<code=500>$$

      


      

        
Conditions

        

          
code=200Response status code equals 200.

          
body_contains=['kw1','kw2']Response body contains any of these keywords (case-insensitive).

          
headers[Name]=valueResponse header Name contains value (case-insensitive). Quote the value if it has spaces: headers[Content-Type]="application/json".

        

      


      

        
Operators

        
code and headers[Name] both accept =, !=, >=, <=, >, < instead of just =. For code the comparison is always numeric. For headers[Name], = / != stay a case-insensitive contains / doesn't-contain check; the four ordering operators (>= <= > <) compare the header's value as a number, and never match if it isn't one.

        
$$QF::<code>=400 AND code<500>$$

        
$$QF::<headers[content-length]>1000>$$

      


      

        
Combining conditions

        
Combine conditions with AND / OR (either case) and parentheses. AND binds tighter than OR, same as most languages — group with parens when you need to be explicit.

        
$$QF::<code=200 AND headers[key]=something>$$

        
$$QF::<(code=200 AND headers[key]=something) OR code=500>$$

      


      

        
Save only matches — ::om

        
Add ::om right after the closing > to change what the condition does: instead of stopping the run, every line still runs, but only the lines whose response matches get saved to the Batch tab.

        
$$QF::<code=200 AND body_contains=['ready']>::om$$
